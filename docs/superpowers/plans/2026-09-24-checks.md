## Step 3: session signals

Hermes auxiliary Responses requests derive and send `prompt_cache_key` in the request body:

```text
/home/hermes/.hermes/hermes-agent/agent/auxiliary_client.py:1534-1540
if not (is_xai or is_github) and "prompt_cache_key" not in resp_kwargs:
    scope = _cache_scope_from_session_id(_runtime_main_value("cache_scope") or _runtime_main_value("session_id"))
    cache_key = _content_cache_key(resp_kwargs["instructions"], resp_kwargs.get("tools"), scope)
    if cache_key:
        resp_kwargs["prompt_cache_key"] = cache_key
```

The Hermes runtime publishes both `session_id` and the rotation-stable `cache_scope` (`auxiliary_client.py:2694-2723`), with `cache_scope` preferred for this key. No `X-Session-ID` header was found in the auxiliary client path.

OMP uses the same body signal. `packages/ai/src/auth-gateway/server.ts:168-173` resolves or derives a stable prompt-cache key and sets both `opts.promptCacheKey` and `opts.sessionId`; `packages/ai/src/compaction/compaction-v2-streaming.ts:217-218` emits `prompt_cache_key` on the Responses body. The gateway also accepts `x-prompt-cache-key`, `x-session-id`, and related headers (`packages/ai/src/auth-gateway/http.ts:105-125`).

CLIProxyAPI's session extraction priority is explicit Claude/Codex/OpenCode/pi headers, then body `session_id`/`prompt_cache_key`, then derived identity, then a stable first-message hash (`sdk/cliproxy/auth/selector.go:1541-1618`). Therefore the router can use `prompt_cache_key` when present and otherwise use the host's derived/hash fallback.
